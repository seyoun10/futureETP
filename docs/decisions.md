  - 혼합 차트의 지수 흐름은 C-a 봉차트와 겹친다.
  - 가격 위 밴드는 "현재 가격이 얼마나 드문가"를 가격 단위로 바로 보여 주고, 유사 서비스의 익숙한 차트 형태와 맞는다.
  - 기준일 대비 커브는 하루 동안의 커브 변화를 직관적으로 보여 준다.

## D-004: 기준값 3종과 지수 산출 방식
- 날짜: 2026-10-22 (소급 기록)
- 상태: 확정
- 결정:
  - 대표월물은 전일 거래량 기준으로 정하고, 이전 월물로 되돌아가지 않는다. 최종 거래일에 도달하면 강제로 전환한다.
  - 한국형·미국형은 시장별로 상품 수 기준 다수 규칙을 쓴다. 동률이면 AUM이 큰 쪽을 쓴다.
  - 종가는 정산가를 쓴다. 지수는 세 기준값 모두 수익률 연결 지수(S&P GSCI 방식)로 만들고, 가격 수준 맞춤(back-adjusted)을 적용한다.
  - 혼합 가격이 0 이하인 날은 산출하지 않고, 다음 유효일은 직전 유효일 혼합 가격으로 이어 붙인다(2026-10-22 추가).
  - 해당 기준값의 상품이 없는 원자재는 대표월물로 대신 표시하고 안내한다.
- 근거:
  - 되돌아가지 않는 규칙은 거래량이 엎치락뒤치락할 때 반복 전환을 막는다.
  - 수익률 연결은 ETP NAV처럼 롤 시점의 가격 점프가 없다. 가격 수준 맞춤은 월물 원가격과 같은 단위로 보게 한다.

## D-005: 이격도와 rare 레벨
- 날짜: 2026-10-22 (소급 기록)
- 상태: 확정
- 결정:
  - 이격도는 종가 SMA 기준이다. 이평선은 20/50/100/200일(기본 100), 분포 기간 N은 3/5/10년/전체(기본 10년)다.
  - rare 레벨은 0.1~49.9 범위의 서로 다른 5개 값을 자유 입력한다(기본 5/10/15/20/25).
  - rare-level 선은 현재 분포의 레벨 이격도를 고정해 `이평선 × (1 + 레벨/100)` 밴드로 그린다.
  - 서버는 48개 시계열과 192개 정렬 분포를 미리 계산한다.
- 근거: 정렬 분포가 있으면 자유 입력 백분위도 바로 구할 수 있다. 50은 위·아래 선이 겹쳐 의미가 없다.

## D-006: rare 레벨 알림 규칙
- 날짜: 2026-10-22 (소급 기록, 중복 방지 키는 2026-10-22 교차 검증에서 확정)
- 상태: 확정
- 결정:
  - 로그인 사용자만 쓸 수 있고, 대상 원자재는 1개다.
  - 1시간 배치로 판정하며 CME 거래 시간에만 돈다. 배치 일정은 America/Chicago 기준이다.
  - 위 방향은 고가, 아래 방향은 저가로 판정한다(분포는 종가 기준, D-002).
  - 한 방향에서 여러 레벨에 닿으면 가장 드문 1건만 보낸다.
  - 중복 방지 키는 원자재 + 기준값 + 이평선 + N + 방향 + 레벨 값 + CME 거래일이다.
  - 일일 정산이 실패하면 판정을 멈춘다.
- 근거:
  - 휴장 중에는 시세가 바뀌지 않아 판정이 의미 없다. Chicago 시간대를 쓰면 서머타임이 바뀌어도 거래 시간과 어긋나지 않는다.
  - 키를 판정 조건 전체로 두면, 같은 날 설정을 바꿨을 때 새 조건의 알림이 막히지 않는다.

## D-010: 데이터 모델 초안의 구조
- 날짜: 2026-10-22
- 상태: 확정
- 맥락: Step 2에서 product.md의 계산 규칙·배치·계정 규칙을 담을 논리 모델을 정했다. DB 종류는 아직 정하지 않았다(TODO 2단계).
- 결정: 세부는 `data-model.md`가 기준이다.
  - 데이터 모델은 product.md에서 분리해 `data-model.md`에 둔다.
  - 대표월물 이력은 별도 테이블 없이 `roll_weight`(basis=FRONT, 비중 1)로 표현한다. 세 기준값을 같은 구조로 다룬다.
  - 지수는 원래 값만 저장하고 가격 수준 맞춤 비율은 `index_scale` 한 행으로 둔다.
  - 커브는 저장하지 않고 `daily_bar`·`intraday_snapshot`으로 조회 시 만든다.
  - 알림 중복 방지 기록과 보류 큐를 `alert_record` 한 테이블로 처리하고, D-006 키 7개 + 사용자에 유니크 제약을 건다. 상태는 SENT/HELD/SUPPRESSED/FAILED다.
  - Apple refresh token은 `apple_credential`로 분리한다.
  - ETP는 상품(`etp_product`)과 시리즈(`etp_series`) 1:N으로 ETN 후속 시리즈를 표현한다.
  - 배치 실행 기록(`batch_run`)으로 마지막 성공 시각과 "일일 정산 실패 시 알림 판정 중지"를 판단한다.
- 근거:
  - 기준값별로 구조가 같아야 지수·이격도 계산 코드를 하나로 쓸 수 있다.
  - 맞춤 비율은 매일 바뀌므로 과거 지수를 매일 다시 쓰지 않으려면 비율을 따로 둬야 한다.
  - 커브는 원천 데이터로 바로 만들 수 있어 중복 저장할 이유가 없다.
  - 유니크 제약으로 중복 발송을 DB 수준에서 막고, 보류 건도 "그날 보낸 것"으로 같은 규칙을 적용할 수 있다.
